## 关键发现

### 1. 行情接口不需要市场后缀

`ak.fund_etf_hist_em(symbol="510300", adjust="qfq")` 直接以 6 位代码工作，跨市场（SH / SZ）都能用。返回字段稳定：`日期`、`收盘`等。

实施意义：

- spec 中"输入规范 · 市场后缀补全规则"可以移除。第一版接受 6 位代码，去除 `.SH` `.SZ` 后缀（如果用户输入了），不再需要根据首位数字推断市场。
- ETF 代码标准化函数只负责：去空格、提取 6 位数字、校验是否为 6 位数字。

### 2. Top10 权重总和分布极广，且 B 分数对宽基 ETF 偏低

| 代码 | top10 权重总和（%） | 解读 |
| - | - | - |
| 510500 中证500ETF | 6.02 | 全持仓 500 只，top10 极度分散 |
| 510300 沪深300ETF | 21.99 | top10 占比中等偏低 |
| 513100 纳指ETF | 42.15 | 海外宽基中等集中 |
| 510050 上证50ETF | 50.82 | 50 只成分股，集中度高 |
| 159915 创业板ETF | 51.89 | 集中在头部成长股 |
| 512880 证券ETF | 54.95 | 单行业 ETF |
| 159949 创业板50 | 64.01 | 窄基集中度最高 |

实施意义：

- 当前 `ak.fund_portfolio_hold_em` 实际返回的是多季度叠加快照（见下文），现有 `fetch_holdings.py` 直接 `head(10)` 取前 10 行，并非"按权重降序的最近一期前十大"。**这是预先存在的不严谨，阶段 2 必须修正**：取最新季度披露 + 按权重降序后再取前 10。
- spec 已说明：第一版只用披露权重，不重新缩放到 1。这条对宽基 ETF 尤其关键 —— 510500 的 top10 总和才 6%，如果错误归一化到 1，B 分数会被夸大 10 倍以上。
- 解释文案需要在 B 分数较低时区分两种情况："底层不重叠" vs "本就无法看清全貌（前十大估算覆盖率低）"。

阶段 2 持仓拉取的伪代码（与现有 `fetch_holdings.py` 不同的部分）：

```python
df = ak.fund_portfolio_hold_em(symbol=code, date=year)
if "公布日" in df.columns:
    latest_publish = df["公布日"].max()
    df = df[df["公布日"] == latest_publish]
df = df.sort_values("占净值比例", ascending=False).head(10)
```

如果该字段名在最新版 AKShare 中不同，再做适配。

### 3. 非股票成分 ETF 没有持仓数据

518880 黄金 ETF：`ak.fund_portfolio_hold_em` 在 2024 / 2023 两个年度都返回空，因为它跟踪商品而非股票，没有股票持仓快照。

实施意义：

- spec 已规定 B 失败时该 ETF 标记为"成分数据不足"，但需要在错误处理段补充一句："对非股票成分 ETF（如黄金、债券、商品），第一版仅 A 分数可用"。
- 涉及黄金/商品/债券 ETF 时，所有 pair 的 B 都不可用，pair status 应为 `partial`，仅展示 A 分数。

### 4. 行情接口已是前复权，不需用户介入

`fund_etf_hist_em(adjust="qfq")` 已用前复权收盘价。日收益率公式直接用：

```ts
dailyReturn[i] = close[i] / close[i - 1] - 1
```

不需要再做除权调整，避免阶段 1 计算核心引入额外字段。
