# 仓库精简与目录语义设计（Repository Slim）

- **状态**：已获产品方口头认可（2026-05-09）；**实施**：同日批 C 已移除 `.claude/skills/`（`python-utils/` 保留）。
- **总路线**：方案二 —— 在清晰语义基础上，用可验证清单分批删除/忽略，避免误删产品依赖
- **优先级**：B（目录语义）→ C（维护成本）→ A（仓库体积）

---

## 1. 目标与非目标

### 1.1 目标

- **B**：贡献者能较快判断「哪些是线上产品、哪些是数据脚本、哪些是编辑器/ Agent 配套、哪些是文档、哪些是本地产物」。
- **C**：减少双轨文档与无约束堆积；删除或迁出前有固定验证步骤。
- **A**：在不影响 B、C 的前提下缩小克隆体积（例如评估臃肿的技能包副本）。

### 1.2 非目标

- 不改变产品功能范围（本设计不写业务需求变更）。

---

## 2. 目录语义（优先级 B）

读仓库时采用以下稳定分工（命名可调，**职责**不变）：

| 区域                   | 含义                                                                                            | 新人默认是否必读 |
| ---------------------- | ----------------------------------------------------------------------------------------------- | ---------------- |
| `src/`                 | 唯一线上产品（Next App Router、组件、API）                                                      | 是               |
| `scripts/`             | 数据拉取、离线探测、与 Vercel 运行时无关的批处理（如 Python）                                   | 改数据管线时     |
| `python-utils/`        | 独立脚本/实验；**非**产品运行时依赖，文档中标注为可选                                           | 默认否           |
| `doc/`                 | **全仓库说明类文档根目录**（评审、规格、superpowers 笔记等）                                    | 按需             |
| `doc/superpowers/`     | 长期规格（`specs/`）与探测/验证笔记（`notes/`）                                                 | 规划功能时       |
| `.github/`             | CI/CD                                                                                           | 发版/排障时      |
| `.cursor/`、`.agents/` | 编辑器 / Agent 配套；**不再**内嵌 `.claude/skills/`（已移除以减小克隆体积）；不参与 Vercel 构建 | 可整体视为工具箱 |

**本地产物**：测试截图、Playwright 输出、临时对齐图等，统一进入约定目录（如 `playwright-artifacts/` 或 `artifacts/`），并列入 `.gitignore`，避免散落在仓库根目录。

---

## 3. 文档统一（硬性约束）

- **原 `docs/` 下全部内容**合并至 **`doc/`**，保持子路径结构：`docs/superpowers/...` → `doc/superpowers/...`。
- 迁移完成后 **删除空的 `docs/` 目录**，仓库内只保留 `doc/` 作为文档根。
- **新建**规格、笔记、说明类 Markdown：**仅**写入 `doc/`（含 `doc/superpowers/...`）。
- **引用更新**（实施阶段执行）：全文检索 `docs/` 并替换为 `doc/`，至少覆盖：
  - `src/` 内注释与文档指针
  - `doc/superpowers/` 内互链
  - `.cursor/rules/generated-docs-in-doc-dir.mdc`（删除与「勿动 `docs/`」相矛盾的条目，改为「文档仅在 `doc/`」）

**风险**：外部站点若链到 `.../docs/...` 的固定 URL，迁移后可能 404；若存在需单独更新外链。

## 4. 维护策略（优先级 C）

### 4.1 三类资产

| 类别              | 含义                                                                              | 允许动作                          |
| ----------------- | --------------------------------------------------------------------------------- | --------------------------------- |
| **P0 产品依赖**   | `pnpm build`、页面/API、部署流水线直接或间接依赖                                  | 仅重构/移动；删除前必须证明无引用 |
| **P1 开发者工具** | `.cursor/`、`.agents/`、本地脚本、多数评审文档（原内嵌 `.claude/skills/` 已移除） | 可删、可迁出仓库；克隆者不必具备  |
| **P2 本地产物**   | 截图、Playwright 输出、临时图、日志                                               | **优先 `.gitignore`**，默认不提交 |

### 4.2 删改前最小验证

每批改动建议至少：

- `pnpm run lint`（若项目惯例保留）与 `pnpm run build`
- 对照 `.github/workflows/deploy.yml`，确认无步骤依赖拟删路径
- 对拟删 Python：在仓库内搜索脚本名、模块路径、文档硬链，确认无 CI/README 绑定

### 4.3 分批节奏

- **批 A**：补充 `.gitignore` + 根目录或 README 增加「仓库地图」短节（指向本节表格）
- **批 B**：删除或迁出已证明 **零引用** 的脚本/重复工具目录
- **批 C（2026-05-09）**：已删除仓库内 `.claude/skills/` 副本；替代方案为全局 / 用户级 OpenSkills 与 Cursor `agent_skills`（见 `AGENTS.md`）。

## 5. 体积与工作顺序（优先级 A）

执行顺序固定为：

1. **B**：taxonomy + 地图文案 + 产物目录 ignore
2. **C**：批 A → 批 B → 批 C，每批「归类 → 验证 → 再删」
3. **A**：最后优化克隆体积（如缩减重复技能包）；**禁止**为省体积先动 `src/` 且无验证

---

## 6. 验收标准（设计层面）

- 存在单一文档根 `doc/`，且无并列的 `docs/` 目录。
- 「仓库地图」可被新贡献者在 5 分钟内读完并对照目录理解职责。
- 任意删除大块目录的 PR 均附带：归类（P0/P1/P2）、引用检索说明、构建/工作流自检结果。
