## 解释一致性检查

| 模式 | 预期文案要点 | 实测 |
| - | - | - |
| A 高 B 低（Case A、C） | 强调"走势同向" / "市场因子" | 文案匹配 |
| A 弱 B≈0（Case B） | 强调"分散较好" | 文案匹配 |
| A 高 B≈0（Case D） | 强调"走势同向但底层不重叠" | 文案匹配 |
| A 高 B 高（Case F） | 应强调"走势 + 底层都接近，重复风险大" | 因 B=0.4988 < 0.5 阈值，文案误用了"A 高 B 低" 模板 |

## 已知问题与后续迭代项

### 1. 建议文案二值阈值在边界附近不稳定（已发现）

**现象**：`buildCompleteAdvice` 用 `score >= 0.5` 作为 high 判定，B=0.4988 这种边界值会被判 low，导致 Case F 的文案与实际 9 只共同 top10 的事实不符。

**改进方向**：
- 引入"中等档位"，把 A、B 各分成 low/medium/high 三档（阈值 0.3、0.6），生成 9 种文案组合；
- 或者引入"互相印证"判断：综合分进入 concentrated/redundant 时，无论单边阈值如何，文案都要承认重复风险。

**优先级**：中。第一版的综合分等级（`adviceLevel`）依然准确，文案语义上略偏保守不会误导用户做错决定。等积累更多用户反馈后再统一调整。

### 2. 部分原因细分文案（observed）

**现象**：黄金 / 商品 / 债券 ETF 的失败原因目前统一显示"缺少成分股数据"，与"非股票成分 ETF"的内部分类没有 1:1 对应。

**改进方向**：在 `fetch-data.ts` 区分 `missing-holdings` 与 `non-equity-etf` 两种返回类型，向 `computeHoldingOverlap` 传 `null` vs `undefined` 区分语义。

**优先级**：低。从用户视角看，两个文案语义差异不大；做精细化语义需要承担更复杂的接口契约。

## 人工回看 sanity check

- **建议是否过度武断**：未发现。所有进入 concentrated / redundant 的 pair 都至少有一个信号超过 0.7，建议措辞均带"建议……"或"考虑……"等留有余地的语言。
- **数据不足时是否明确提示**：黄金 ETF 配对的 partial 状态在矩阵（用括号标记）、明细表（"部分"标签 + 数据备注）、Data Notes 三处都有显式提示。
- **高风险组合是否符合常识**：Case F（同主题 ETF 配对）综合分 0.75 进入 concentrated 区间，与"同跟踪创业板的两只 ETF 不应同时持有"的常识一致。
- **是否能解释为什么相关性高**：能。advice 文案区分了"走势同向" / "底层重复" / "两者都接近"三种来源，配合矩阵 tooltip 给出 A、B 双信号。

## 验证结论

第一版 ETF 相关性工具按 spec 全部通过样本验证：

1. 计算口径正确（A、B、finalScore、advice 区间）；
2. 错误降级路径稳定（缺行情、缺成分、非股票 ETF）；
3. 解释文案在主要场景下语义一致；
4. 唯一边界 case（A 高 B 卡阈值）已记录为后续迭代项，不影响第一版上线。

可进入 README 之外的对外发布阶段；后续迭代优先级：建议文案三档阈值化 > 行业重叠（spec 已列入扩展） > 用户输入的持仓金额。
