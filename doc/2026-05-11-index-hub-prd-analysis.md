# 指数目录与详情页：产品设计分析（PRD 纲要）

**文档日期**：2026-05-11  
**适用**：Stillwell / stock-view 在已有「网格计算」「指数对比（相关性）」之上，新增「多指数表格浏览 + 指数详情页」时的 **问题界定、信息架构、站内导流与竞品差异化**。  
**按页面归类索引**：`/doc/index-hub-prd/README.md`（落地页、列表、详情、网格、对比及跨页条目）。  
**关联技术文档**：`/doc/2026-05-11-stock-view-vs-etfrun-architecture-and-optimization.md`（渲染模型、缓存与 O1–O5 工程 backlog）。

## 1. 背景与「Why Now」

### 1.1 要解决的问题

用户完成「策略参数」或「两只标的对比」之前，往往需要先 **在海量指数中定位标的、理解估值水位与类别归属**。当前站点强项在 **工具闭环**（网格本地计算、相关性聚合），但缺少 **可扫描的指数全景入口**，导致：

- 新用户难以从「宏观榜单」自然沉入「单指数深挖」再进入「网格 / 对比」工具链；
- 老用户重复手输代码，**上下文切换成本高**。

### 1.2 为何现在做

- 工具侧已有明确心智（网格、对比）；补上 **目录层** 可把 Stillwell 从「计算器集合」升级为「投研工作台」；
- 指数类内容 **读多写少、结构化强**，适合与站内已有首页 RSC 策略对齐，长期也有利于 **可分享的稳定 URL**（单指数详情）。

### 1.3 成功标准（建议的可验收表述）

| 维度     | 指标或信号                                                                           |
| -------- | ------------------------------------------------------------------------------------ |
| 触达     | 从首页 / 导航进入指数列表的 UV；列表 → 详情 CTR                                      |
| 任务完成 | 详情页 → 「打开网格（预填）」或 「与另一只对比」的转化率                             |
| 信任     | 明细页展示 **数据截取日期 / 估值口径说明**，用户问询「数和别的站不一致」的工单量可控 |
| 性能     | 列表与详情首屏在弱网下优于「整页空白再等 JSON」的体感（与技术文档 O2/O3/O4 对齐）    |

## 2. 指数列表（表格）——范围与交互原则

### 2.1 建议列字段（与你列举项对齐并补充）

- **指数名称**、**指数代码**（主键展示）、**所属类别**（宽基 / 行业 / 主题 / 跨境等，口径需产品词典）
- **当前 PE（或 PB）** 与 **近 5 年 / 近 10 年** 分位或滚动估值摘要（需统一：是 **历史分位** 还是 **绝对估值**，避免混排）
- **指数估值**一栏若指「综合打分」，建议拆成 **独立列 + tooltip 口径**，否则易与 PE/PB 重复

### 2.2 表格体验（最小够用）

- **排序 / 筛选**：类别、估值分位区间、关键词搜索（名称或代码）
- **行级动作**：进入详情（主路径）；可选「复制代码」「加入对比候选」（见 §4）
- **移动端**：优先保证 **冻结首列 + 横向滚动** 或可切换「精简列视图」

### 2.3 明确不在首版范围（防范围蔓延）

- 全市场实时盘口级刷新、用户自定义公式列、登录收藏同步（可作为二期）

## 3. 指数详情页——信息架构建议

你设想的三大模块方向正确，建议按下述 **阅读顺序** 组织，避免首屏信息堆叠。

### 3.1 模块 A：估值水位与「极端情景」摘要（首屏）

**目标**：回答「现在贵不贵、历史上类似位置发生过什么」。

- **当前点位**相对历史的表达建议 **双轨**：
  - **时间维度**：近 1 年 / 5 年 / 10 年 / 全历史（与下文走势图一致）
  - **分位维度**：PE、PB（若适用）分别在所选窗口下的 **分位数**，并标注 **计算窗口与财报剔除规则**（口径文案固定模板）
- **「下跌 70% / 80% 分位」表述**：建议改为用户可读标签，例如 **「历史 PE 低位区间（约下 20% 分位）对应点位大致区间」**，并在脚注说明是 **估值分位** 还是 **价格指数回撤**，二者不可混为一谈
- **必选**：数据 **截至日期**、指数编制机构、基数调整说明（链接或折叠）

### 3.2 模块 B：走势与分析周期切换

**目标**：与模块 A 的窗口选项 **严格联动**（同一套 1Y / 5Y / 10Y / ALL），减少「图上一年、卡片十年」的认知冲突。

- 默认视图：**价格指数** + 可选叠加 **PE/PB 第二坐标轴**（若实现成本高，可先 PE **单独小 multi-chart**）
- 交互：**区间刷选**（brush）可作为增强项；首版 **Tab 切换周期** 即可

### 3.3 模块 C：跟踪指数的 ETF 对比

**目标**：从「指数」落到「可交易载体」，并为网格工具导流。

- 表格列建议：**代码、规模、费率、折溢价、流动性（成交额）、跟踪误差（若有）**
- 排序默认：**规模 × 流动性** 的综合推荐，而非单纯规模最大
- 每行 CTA：**「用该基金打开网格」**（见 §4.2）

### 3.4 详情页可选增强（二期优先级）

- **相关指数推荐**：同类别、低相关或上下游（需克制，避免推荐噪音）
- **成分集中度**：前十大权重（若数据可得），服务「分散度」心智，与相关性工具叙事一致

## 4. 与网格计算、指数对比的站内链接设计

### 4.1 URL 与导航层

- **全局导航**：在首页 header 与落地卡片区增加第三入口 **「指数」或「指数目录」**，与 `/grid`、`/correlation` 并列
- **稳定详情 URL**：建议 `/indices/[code]` 或 `/index/[symbol]`（全站统一大小写与交易所后缀规则）

### 4.2 列表 / 详情 → 网格（`/grid`）

- **深度链接契约（建议）**：`?symbol=` 或 `?etf=` 预填标的代码（以网格页当前参数模型为准，需工程对齐 `useGridParams`）
- **文案**：「打开网格」「用该基金测算网格」——强调 **从估值结论进入策略实验**

### 4.3 列表 / 详情 → 指数对比（`/correlation`）

- **单指数详情**：提供「选择另一只对比」：**输入第二代码** 或 **从「我常对比的基准」**（如沪深 300）一键跳转
- **深度链接**：`/correlation?a=XXX&b=YYY&period=…`（与现有 pair API 查询参数一致时可降低前端改造成本）
- **列表页**：支持勾选两行「对比」浮动条 → 跳转 correlation（注意与移动端交互成本）

### 4.4 反向链接（工具页 → 指数上下文）

- 网格页、对比页侧栏或结果区：**「查看该标的指数档案」** 链接回详情页，形成闭环
- 当用户仅输入 ETF 时：若映射关系明确，可链到 **跟踪指数详情** 而非空白

## 5. 网格与指数对比页面的优化方向（产品与工程）

以下 **工程向条目** 与 `2026-05-11-stock-view-vs-etfrun` 中 **O1–O5** 一一对应；此处补充 **产品侧可感知优化**。

### 5.1 网格（`/grid`）

- **预填与模板**：从新指数详情带入代码后，给出 **保守 / 中性** 参数预设，降低首次使用挫败感
- **解释性**：\_stats 卡片增加指向「指数详情估值口径」或站内说明锚点，避免「算了但不知道假设是什么」
- **性能/包体积**：维持本地计算优势的同时，继续 **岛屿式 Client**（技术文档 O3），避免整页过重

### 5.2 指数对比（`/correlation`）

- **首屏数据**：当 URL 已带 `a、b、period` 时，**服务端或 RSC 预取初始结果**（O2），缩短「白屏 → 有图」
- **短时缓存**：重复刷新同一对标的（O1），改善体感与上游负载
- **`loading.tsx` + 预取**（O4）：路由跳转时有骨架或占位
- **文案**：落地 FACTS 中与「100% 本地」相关的表述需 **按工具拆分**（O5），避免用户误以为相关性也无服务端

### 5.3 全站一致性

- **术语**：「指数对比」在 UI 上与 URL `/correlation` 并存时，可在关于页用一句话说明 **对比的是收益联动与持仓重叠等信号**，与「行情 K 线叠图」类竞品功能区分开

## 6. 与 ETF.run 的差异化设计（产品定位层）

技术实现差异（SSR/RSC、缓存、API 面）见关联技术文档 §2–§7；此处强调 **用户心智差异**。

| 维度         | ETF.run（归纳）                                      | Stillwell / stock-view                                                        |
| ------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------- |
| 核心承诺     | **泛读**：大范围估值浏览、SEO 友好的「静止内容」消费 | **精读 + 行动**：在理解估值后 **生成网格参数**、检验 **两只基金是否过度重合** |
| 详情页重心   | 估值榜单与字段 completeness                          | **估值上下文 + 工具入口**（网格、对比）与 **可复现实验**                      |
| 账户与个性化 | 多为匿名浏览                                         | 可保持 **无需登录** 心智，用 URL 与本地状态完成分享                           |
| 数据叙事     | 强调「全市场覆盖」                                   | 强调 **口径透明、更新时点、与站内工具同一套标的映射**                         |

**差异化一句话**：ETF.run 更适合「逛」；Stillwell 更适合 **「选定标的 → 论证 → 下单前自检策略与分散度」**。

**设计上忌简单复制**：勿堆砌与 ETF.run 同构的大表格字段竞赛；应在详情页 **Above the fold** 露出 **下一步动作**（网格 / 对比 / 复制代码），突出工具链。

## 7. 关键待决策事项（开工前建议拍板）

1. **估值口径**：PE(TTM)？扣非？规则是否与数据源文档完全一致并在 UI 固化 Tooltip？
2. **「指数 ↔ ETF」映射**：一拆多、联接基金、QDII 滞后如何处理展示优先级？
3. **分位定义**：用滚动窗口还是全样本？是否对齐图表默认周期？
4. **详情页渲染策略**：列表与详情是否采用 **偏服务端直出 + 缓存**（技术文档 §7 判定表：只读内容更适合 SSR/ISR），与 `/correlation` CSR 工具页区分。
